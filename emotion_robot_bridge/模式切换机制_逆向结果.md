# 模式切换机制逆向结果（Phase 0 破解）

> 调查日期：2026-08-19
> 方法：反汇编 `sim2real_master_node`（`/home/nvidia/sim2real/install/bin/sim2real_master_node`，
> aarch64 ELF，**未 strip**），结合 `fsm.h` 源码与编译后字符串。
> 结论：**Phase 0 遗留问题（ExecDefault → ExecCustom 的按键序列）已完全破解。**

---

## 一、之前的卡点

- 机器人启动后自动进入 `ExecDefault`（行走模式，FSM=5）。
- cheer/hello 动作（`custom_action.yaml`：cheer=rt+a，hello=rt+x）只能在 `ExecCustom`（FSM=6）执行。
- 直接发 `rt=1.0,a=1.0` 到 `/joy_msg` 会被识别（日志 `cheer:amp`）但**不执行**。
- 一直不知道如何从 ExecDefault 切到 ExecCustom。

## 二、破解方法

1. 确认机器人实际运行的是 `install/bin/sim2real_master_node`（50MB，未 strip）。
2. `nm -C` 定位到 `hightorque::MasterNode::joyMsgCallback`（0x136d2a0，520 字节）。
3. `aarch64-linux-gnu-objdump -d` 反汇编该函数，逐条还原分支逻辑。
4. 对照 `fsm.h` 的 `joy_table1/joy_table2/default_table` 与编译后 `boost::msm` 转移表字符串。

## 三、关键结论

### 1. joyMsgCallback 按键 → FSM 事件映射（反汇编确认）

| Joy 字段 | 值 | FSM 事件 | 效果 |
|----------|----|----------|------|
| `center` | == 1.0 | `DefaultModeEvt` | 任何状态 → ExecDefault（行走） |
| `dpad_horizontal` | == +1.0 | `LastOptionEvt` | 菜单上一项 |
| `dpad_horizontal` | == -1.0 | `NextOptionEvt` | 菜单下一项 |
| `a` | == 1.0 | `ConfirmEvt` | 确认进入当前候选模式 |
| `b` | == 1.0 | `ProtectionShutdownEvt` | 保护关机 / 退出执行态 |

**前置条件**：菜单导航（dpad/a/b）只在 `lt < -0.1 && rt < -0.1`（左右扳机完全松开）时生效。
`center` 不受此限制。每个 FSM 事件处理后 joyMsgCallback 会 `sleep 200ms`。

> ⚠️ 扳机「松开」值是 **-1.0**（不是 0.0）。软件发布时 `lt`/`rt` 必须置 `-1.0`，
> 否则会被当作「扳机已按下」，dpad/a/b 事件被跳过（已在上方 robot_action_client.py 的 NEUTRAL 中落实）。

### 2. FSM 菜单结构（fsm.h）

```
Init(0)
  -Next-> CandidateDefault(2)
           -Next-> CandidateCustom(3)
                    -Confirm-> ExecCustom(6)   ← cheer/hello 在此执行
           -Confirm-> ExecDefault(5)           ← 行走（启动默认）
```

- 启动时 `init()` 调用 `process_event(StartEvt)` → `Init → ExecDefault`（自动进入行走）。
- **ExecDefault 没有直接回菜单的转移**（只有 `ProtectionShutdownEvt → ProtectionShutdown` 一条出口）。

### 3. ExecDefault → ExecCustom 按键序列

```
b               → ProtectionShutdown(8)
b               → Init(0)
dpad_horizontal = -1.0  → CandidateDefault(2)
dpad_horizontal = -1.0  → CandidateCustom(3)
a               → ExecCustom(6)
```

之后 `rt=1.0, a=1.0`（cheer）或 `rt=1.0, x=1.0`（hello）即可执行。

### 4. 回 ExecDefault

任意状态按 `center=1.0` → `DefaultModeEvt` → ExecDefault。

## 四、⚠️ 安全警告

切换序列会经过 `ProtectionShutdown` 和 `Init`：
- `Init` 状态电机命令置零（`ActSetMotorZero`），机器人**失力**。
- 站立/行走中切换会导致机器人**跌倒**。

**切换前必须让机器人处于稳定姿态**（坐姿 / 跪姿 / 由人扶住），
或对机器人进行支撑，切勿在站立或行走时执行模式切换。

## 五、已落地实现

- `robot_action_client.py` 的 `JoyEmulatorClient` 已实现：
  - `switch_to_custom_mode()`：按上述序列切换并读取 `/fsm_state`（std_msgs/Int32）验证。
  - `switch_to_default_mode()`：按 `center` 切回行走。
  - `trigger_action()`：先确保 ExecCustom，再发动作按键。
- `bridge_config.json` 新增：`ensure_custom_mode`、`mode_switch_interval`、`action_hold`、`fsm_state_topic`。

## 七、遗留 / 可选

- `joyMsgCallback` 里 `a`/`b` 没有做边沿检测（只在值精确等于 1.0 时触发），
  因此软件发布单条按键消息即可触发事件，无需真实手柄的按下/释放边沿。
- 未验证：`b` 键连续两次之间的 `ProtectionShutdown` 是否会被 20Hz `TickEvt + GuardShutdown`
  自动提前带回 Init（若会，第二次 `b` 在 Init 上是 no-op，序列依然成立）。
- 其它可能的直接接口（`change_state` 服务、`lowlevel_controller` actionlib）存在于二进制中，
  但**主控节点 init() 只订阅了 /joy_msg + JointState + Imu、只发布 /fsm_state + version**，
  未暴露这些接口，因此模式切换只能走 /joy_msg。
