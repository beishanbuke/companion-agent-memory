# 2026-07-07 开发记录

## Memory Router v2

今天完成了 Memory Router 的第二版规则路由，并将 `rule_based_v2` 设置为默认策略。`rule_based_v1` 继续保留，可用于对照和回滚。

### 优化目标

- 降低无关场景调用长期记忆的概率。
- 避免 Situation Router 的分类结果直接否决合理的记忆请求。
- 将“是否需要记忆”和“应该检索哪些 Tier”拆开处理。
- 提高路由结果的可解释性和可调试性。
- 控制注入上下文的记忆总量。

### 主要改动

1. 新增 `RuleBasedMemoryRouterV2`，并通过版本化 facade 注册。
2. 调整路由优先级：
   - 用户显式禁用记忆
   - 短期上下文请求
   - 第三方或通用受众请求
   - 显式长期记忆查询
   - 个性化背景记忆
   - 默认不使用记忆
3. Situation Router 只作为弱提示，不再因为 `coding_helper`、`tool_task` 等分类结果直接关闭记忆。
4. 为五类 Tier 独立评分：
   - `profile`
   - `preferences`
   - `long_term_goals`
   - `episodic_events`
   - `safety_notes`
5. 使用 `conversation_history` 识别与记忆相关的短追问。
6. 使用 `current_memory_snapshot` 过滤实际不存在的 Tier：
   - background 模式没有相关可用记忆时，退化为不检索。
   - explicit 模式即使没有匹配记忆，仍保留显式记忆查询语义，以便回答“没有相关记录”。
7. `MemoryRouteDecision` 新增可观测字段：
   - `confidence`
   - `signals`
   - `tier_scores`
8. 执行全局记忆预算：
   - 默认最多注入 3 条记忆。
   - 先执行单 Tier 限制，再按照 Router 给出的 Tier 优先级执行全局裁剪。
9. 评测脚本现在会把样本中的 `memory_snapshot` 传给 Router。
10. 新增 `--fixed-situation` 参数，可绕过 Situation Router，单独评测 Memory Router。
